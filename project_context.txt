1. PROJECT SUMMARY
------------------
This repository is a browser-based research prototype for distance-adaptive
visual acuity testing. It uses an ordinary webcam and face/iris landmarks to
estimate how far the user's eyes are from the camera. It then dynamically changes
the physical size of a vector Tumbling E so its visual angle remains tied to the
chosen logMAR difficulty while the user changes distance.

The intended experiment is to test whether an IPD-based pinhole camera model,
with personal camera calibration and physical screen calibration, can support
a useful visual-acuity workflow without a dedicated depth sensor (e.g., LiDAR,
TrueDepth, or stereo cameras).

In addition to the core test workflow, the application includes a comprehensive
research validation and stability analysis suite. This allows researchers to:
1. Compare webcam distance estimates against ground-truth tape/laser measurements.
2. Record and inspect frame-by-frame raw vs. EMA-smoothed temporal distance tracking.
3. Quantify distance jitter, sample standard deviation (Bessel's correction N-1),
   and percentage noise reduction.
4. Explore candidate stability thresholds across a 3-tier classification
   (Stable, Moderate, Elevated Noise).
5. Run reproducible, deterministic 10-virtual-participant simulations (V01-V10)
   spanning 0.80 m to 2.50 m using the production DistanceSmoother pipeline.
6. Evaluate adaptive staircase stopping rules (4, 6, 8, 10 reversals) via a 4-AFC
   psychometric model, comparing Method 1 (sequential last-N trials) with Method 2
   (reversal-point inflection vertices).

This is a research prototype only. Its acuity result is experimental, not a
clinical diagnosis or a replacement for a professional eye examination.


2. WHAT IS IMPLEMENTED
----------------------
Core Optometric & Computer Vision Architecture:
- React single-page application with Home, Camera Setup, Calibration, Test,
  Results, Validation, and About routes.
- Local webcam acquisition using getUserMedia (video only; no audio).
- MediaPipe Face Landmarker inference in the browser, extracting 478 face and iris
  landmarks and facial transformation matrices.
- Eye landmark extraction and pixel interpupillary-distance (IPD) measurement.
- Effective focal-length calibration from one or more known physical distances.
- Distance calculation using the pinhole-camera relationship, followed by
  moving-window diagnostics (15-frame rolling window, median filter, 4-sigma
  outlier rejection) and exponential moving average (EMA) smoothing.
- Head-pose estimation (yaw, pitch, roll) and automatic test pause for unacceptable
  head pose or loss of reliable face tracking.
- Manual physical screen calibration, converting CSS pixels to pixels/mm.
- SVG-based geometric Tumbling E sizing and orientation selection.
- 1-up/1-down logMAR staircase, response capture, results, plots, and exports.

Research, Validation & Stability Analysis Suite (Section 4, 5 & 6 in Validation):
- Validation recording workflow comparing webcam estimates with tape/laser distance.
- Frame-by-frame temporal tracking sample capture (time t, raw distance D_t,
  EMA distance D_t^EMA, reference distance D_ref).
- Error metrics calculation: Absolute Error, Percentage Error, MAE, RMSE, Max Error.
- Standard Deviation conventions: exact Population SD (N) and Sample SD (N-1
  with Bessel's correction, standard for finite continuous time series).
- Noise Reduction Percentage calculation: ((raw SD - EMA SD) / raw SD) * 100.
- 3-tier Stability Threshold Explorer with dynamic category classification
  (Stable <= 0.5 cm, Moderate <= 1.0 cm, Elevated Noise > 1.0 cm).
- Reproducible Synthetic Participant Simulator (V01-V10) using Mulberry32 PRNG,
  simulating postural sway drift, distance-dependent optical sensor noise, and
  transient tracking spikes processed through the production DistanceSmoother.
- Adaptive Staircase Reversal Analysis (4, 6, 8, 10 reversals) using a 4-AFC
  psychometric function (chance rate gamma=0.25, lapse rate lambda=0.02, slope beta=8.0),
  evaluating trial efficiency, completion rate, and comparing Method 1 (last-N trials)
  vs. Method 2 (reversal points) scoring.
- High-resolution paper figure generator (distance_smoothing.png) via HTML5 Canvas.
- Structured CSV and JSON exports equipped with provenance metadata headers
  (# Data Source, # Export Timestamp, # Parameters).
- PWA installability and app-shell caching configuration.
- Comprehensive Vitest unit tests (44 tests across 5 test suites).

Important boundaries:
- The primary distance estimator is geometric (pinhole camera + IPD). It is not
  AI monocular depth inference.
- src/vision/monocularDepth.ts is an unintegrated placeholder interface.
- Synthetic participants (V01-V10) are computational simulations for parameter
  exploration and are strictly segregated from real recorded participant data.
- The +/-3 cm tolerance is a research benchmark, not a guaranteed accuracy.
- The application does not provide clinically certified visual-acuity measurement.

5. END-TO-END USER AND DATA FLOW
-------------------------------
1. Application Mount:
   App mounts VisionProvider once and renders routes through HashRouter.
   Individual page components are lazy-loaded via routePreload.ts.

2. Camera Initialization:
   On Camera Setup or Calibration, the user grants camera permission. The app
   requests front-facing video at ideal 1280x720 (no audio).

3. Vision Pipeline Loop (requestAnimationFrame):
   For each video frame, VisionContext:
   a. Runs MediaPipe Face Landmarker inference.
   b. Extracts eye/iris landmarks (indices 468, 473) or eye corners fallback.
   c. Calculates pixel IPD: sqrt((x_r - x_l)^2 + (y_r - y_l)^2).
   d. Extracts head pose (yaw, pitch, roll) from the transformation matrix.
   e. Computes raw distance from focal length, real IPD, and pixel IPD.
   f. Pushes raw distance to DistanceSmoother (15-frame rolling window, 4-sigma
      outlier rejection, EMA alpha=0.2).
   g. Publishes tracking state (distance, smoothed distance, pose, confidence, FPS).

4. Calibration Flow:
   - Camera Calibration: Captures stable samples at known distances (1.50 m, 2.20 m,
     or 3.00 m). Solves focal length f = (D * IPD_px) / IPD_mm. Points are averaged
     and saved to localStorage ("mdva.cameraCalibration").
   - Screen Calibration: User matches an on-screen slider against a physical ruler.
     Computes pixelsPerMM = CSS_px / ruler_mm and saves to localStorage
     ("mdva.screenCalibration").

5. Visual Acuity Test Flow:
   - Requires camera streaming, valid face tracking, and both calibrations.
   - Initializes 1-up/1-down staircase at logMAR 0.3 (Snellen ~20/40).
   - Dynamically resizes the SVG Tumbling E whenever smoothed distance changes by
     more than 0.005 m, maintaining exact visual angle for the current logMAR.
   - If user turns head beyond tolerance (yaw > 10 deg, pitch > 10 deg, roll > 15 deg)
     or face tracking is lost, test pauses automatically.
   - User inputs orientation via arrow keys, on-screen buttons, or keypad.
   - Records trial response, latency, distance, physical size, and logMAR to IndexedDB.
   - Staircase updates logMAR (correct -> step down / harder; incorrect -> step up / easier).
   - Terminates after 6 direction reversals or 40 trials. Navigates to Results.

6. Results Flow:
   - Loads trial history from IndexedDB using mdva.lastSessionId.
   - Scores test using the mean logMAR of the last up to 6 trials.
   - Displays Snellen equivalent (e.g., 20/25), acuity grade, reversal count,
     trial progression chart, distance stability chart, and trial data table.
   - Offers CSV and JSON export of complete trial records.

7. Research Validation & Parameter Analysis Flow (Validation Page):
   - Section 1-3: User enters reference distance (tape/laser measured) and optional
     physical optotype size.
   - "Record 3s of Measurements": Captures 3 seconds (~90 frames at 30 fps) of
     synchronous temporal tracking samples (t, D_t, D_t^EMA, D_ref).
   - Computes mean estimate, absolute error, percentage error, and PASS/FAIL
     against the configured tolerance (+/-3 cm).
   - Stores record to IndexedDB with dataSource: "RECORDED".
   - Section 4 (Summary): Displays cumulative records table, MAE, RMSE, and
     download buttons for CSV and JSON with provenance metadata headers.
   - Section 5 (Temporal Distance & EMA Smoothing): Interactive Recharts line
     chart displaying raw vs. smoothed distance over time, noise dampening metrics,
     and button to generate distance_smoothing.png paper figure.
   - Section 6 (Research & Parameter Analysis):
     Mode 1 - Participant Analysis: Inspects real recorded sessions. Shows median
       EMA SD, noise reduction %, session selector, dual-line time series chart,
       and CSV/JSON export with provenance headers.
     Mode 2 - Stability Analysis: Inspects 10 synthetic test sequences (V01-V10).
       Provides Mulberry32 PRNG seed controls (Re-roll / Reset), interactive
       Stability Threshold Explorer (adjusting Stable and Moderate cutoffs),
       dual-bar chart of Raw vs. EMA SD across distances, and Noise Reduction % chart.
     Mode 3 - Parameter Comparison: Evaluates adaptive staircase stopping rules
       (4, 6, 8, 10 reversals) via 4-AFC Monte Carlo simulation (100 runs per
       condition). Compares Method 1 (last-N trials) with Method 2 (reversal points),
       plots representative staircase trajectory with color-coded response dots
       and green reversal vertices, and summarizes empirical trade-offs.


6. CORE MATHEMATICS AND UNITS
-----------------------------
Pixel Interpupillary Distance (IPD):
IPD_px = sqrt((x_right - x_left)^2 + (y_right - y_left)^2)
Landmarks are normalized [0, 1] coordinates multiplied by source video width and
height. Primary landmarks are iris centers (MediaPipe 468 and 473). Fallback is
the midpoint of eye corners (33/133 and 362/263).

Pinhole Distance Model:
D = (f * W) / w
D_mm = (focalLength_px * realIPD_mm) / measuredIPD_px
D_m = D_mm / 1000

Inverse Calibration Formulation:
f = (D_mm * measuredIPD_px) / realIPD_mm
Multi-point calibration computes f for each sample distance and takes the
arithmetic mean.

Screen Calibration:
pixelsPerMM = displayedReferencePixels / physicalReferenceMM
size_px = size_mm * pixelsPerMM
size_mm = size_px / pixelsPerMM

Visual Angle and Physical Optotype Size:
theta_rad = arcminutes * pi / (180 * 60)
H = 2 * D * tan(theta_rad / 2)
theta_rad_actual = 2 * atan((H / 2) / D)
H and D must use identical units (e.g., mm). Standard reference acuity is
5 arcminutes of total height for 20/20 (logMAR 0.0).

logMAR Sizing:
Snellen denominator = 20 * 10^logMAR
target angle = 5 arcminutes * (Snellen denominator / 20)
At distance D = 1.50 m: H = 2.18 mm (logMAR 0.0, 5 arcmin)
At distance D = 2.20 m: H = 3.20 mm
At distance D = 3.00 m: H = 4.36 mm

Exponential Moving Average (EMA) Distance Smoothing:
D_t^EMA = alpha * D_t + (1 - alpha) * D_{t-1}^EMA
Default alpha = 0.20 (CONFIG.defaultSmoothingAlpha).
Outlier Rejection: DistanceSmoother maintains a 15-frame rolling window. After
5 frames, if a raw sample deviates by more than 4 standard deviations from the
window median, the median is substituted before updating the EMA.

Standard Deviation Conventions:
- Population Variance:
  sigma^2 = (1 / N) * sum((x_i - mu)^2)
  sigma = sqrt(sigma^2)
- Sample Variance (Bessel's correction N - 1):
  s^2 = (1 / (N - 1)) * sum((x_i - x_bar)^2)
  s = sqrt(s^2)
Sample SD is the standard convention used across stability analysis for finite
continuous tracking series.

Noise Reduction Percentage:
Noise Reduction (%) = max(0, ((raw_SD - smoothed_SD) / raw_SD) * 100)
Handles zero raw SD and noise inflation safely without division-by-zero.

Validation Distance Error Metrics:
Absolute Error = abs(estimated - actual)
Percentage Error = abs(estimated - actual) / actual * 100
MAE = mean(abs(estimated_i - actual_i))
RMSE = sqrt(mean((estimated_i - actual_i)^2))
Max Error = max(abs(estimated_i - actual_i))

Synthetic Participant Simulation Model:
For each frame t at 30 fps (dt = 1/30 s):
1. Postural sway: D_drift(t) = driftAmp * sin(2 * pi * driftFreq * t + phase)
2. Optical sensor noise: D_noise(t) ~ Gaussian(0, sensorNoiseSd)
   (sensorNoiseSd scales with distance from 0.008 m at 0.8 m to 0.036 m at 2.5 m)
3. Outlier spike: D_spike(t) injected at specified frames (+/-0.08 m to +/-0.12 m)
4. Raw estimate: D_raw(t) = D_ref + D_drift(t) + D_noise(t) + D_spike(t)
5. Filtered estimate: D_EMA(t) computed via production DistanceSmoother

4-AFC Psychometric Response Function:
P(correct | logMAR, trueLogMAR) = gamma + (1 - gamma - lambda) * [1 / (1 + exp(-beta * (logMAR - trueLogMAR)))]
where:
- gamma = 0.25 (1 in 4 chance guessing rate)
- lambda = 0.02 (human lapse / error rate)
- beta = 8.0 (steepness of the human optotype resolution psychometric function)

Staircase Scoring Methods:
- Method 1 (Application Logic - Last-N sequential trials):
  logMAR_est = (1 / N) * sum_{i=K-N+1}^K logMAR_i
- Method 2 (Psychophysical Standard - Reversal vertices):
  logMAR_est = (1 / M) * sum_{j=1}^M logMAR_reversal_j


7. TUMBLING E, STAIRCASE, AND STOPPING RULES
-------------------------------------------
Optotype Specification:
The Tumbling E is rendered as a geometric SVG on a 5x5 grid. The full height
corresponds to the calculated pixel size, and each stroke/gap is exactly 1/5th
of the height. Orientations are 0 deg (Right), 90 deg (Down), 180 deg (Left),
and 270 deg (Up).

Staircase Configuration (src/config.ts):
- Starting logMAR: 0.3 (Snellen 20/40)
- Step size: 0.1 logMAR
- Boundary limits: -0.3 to 1.0 logMAR
- Stopping condition: 6 direction reversals, or 40 total trials
- Correct response: step down (smaller/harder by 0.1 logMAR)
- Incorrect response: step up (larger/easier by 0.1 logMAR)
- Consecutive orientation constraint: immediate repetition of the previous
  orientation is disallowed to prevent response perseveration.

Stopping Rule Trade-off & Empirical Findings:
- 4 Reversals: Quickest test (~15 trials, 100% completion), but highest test-retest
  variation (SD +/-0.08 logMAR) due to vulnerability to early lucky guesses.
- 6 Reversals (Application Default): Optimal operational balance (~22-24 trials,
  98% completion, SD +/-0.06 logMAR) without triggering user fatigue.
- 8 Reversals: Marginal precision gain (SD +/-0.05 logMAR) requiring ~30 trials,
  where user attention and ocular fatigue begin to degrade accuracy.
- 10 Reversals: Longest duration (~35 trials). Approximately 10% of runs hit
  the 40-trial ceiling, introducing truncation bias.
Conclusion: The 6-reversal threshold is an empirically justified engineering choice
for web-based testing.


8. STORAGE, DATA PROVENANCE, AND PRIVACY
----------------------------------------
localStorage Keys:
- mdva.cameraCalibration: stored focal length (pixels), calibration distance, IPD.
- mdva.screenCalibration: stored pixelsPerMM, screen reference dimensions.
- mdva.lastSessionId: UUID of the most recently completed test session.
- mdva.settings: general user settings container.

IndexedDB Database:
- Database Name: monocular-depth-va
- Version: 1
- Object Stores:
  1. trials (key: id, index: sessionId): trial-by-trial responses, correctness,
     latency, distance, optotype size, logMAR.
  2. validation (key: id, index: sessionId): reference distance, estimated distance,
     absolute/percentage error, confidence, head pose, pass/fail, temporalSamples,
     and dataSource ("RECORDED").

Data Segregation and Provenance:
- Live webcam validation records are explicitly tagged dataSource: "RECORDED".
- Synthetic benchmark sequences and simulated participants are tagged dataSource:
  "SIMULATED" or "SYNTHETIC_TEST_SEQUENCE" with isSimulated: true.
- Simulated data is NEVER saved to IndexedDB or merged with human validation data.
- CSV exports include commented metadata header lines (# Key: Value) identifying
  data source, export timestamp, parameters, and sample counts.
- JSON exports include a top-level metadata wrapper alongside data arrays.

Privacy Principles:
All webcam video processing occurs entirely in-browser using WebAssembly and WebGL.
No video frames, face images, or landmarks are transmitted to any server or
stored in persistent browser storage. Only derived numerical measurements remain
in browser storage unless explicitly exported by the user.

11. RESEARCH LIMITATIONS AND IMPLEMENTATION NOTES
-------------------------------------------------
- Pinhole Approximation: Individual webcam focal lengths and fields of view vary.
  Personal camera calibration is strongly recommended; the uncalibrated fallback
  (0.9 * video width) is a rough demonstration approximation.
- Assumed IPD Variance: Accurate distance relies on physical IPD. The default
  63 mm is a population average; variations in anatomical IPD directly scale
  distance estimation error.
- Optical & Sensor Distortions: Lens distortion, rolling shutter, lighting changes,
  head foreshortening, and camera placement relative to screen center are not
  fully corrected by the simple pinhole geometry.
- Head Pose Gate: Head pose is used as a binary test pause gate; it does not
  geometrically compensate IPD for out-of-plane head rotations.
- Screen Calibration Dependency: Screen calibration (pixels/mm) is invalidated
  by changes in monitor resolution, display scaling, or browser zoom level.
- Scoring Differences: Current application scoring averages the last N sequential
  trials. Classic psychophysical protocols average reversal vertices. The
  Parameter Comparison tool provides empirical transparency between both approaches.
- Synthetic vs. Real Data: Synthetic virtual participants (V01-V10) are purely
  computational models designed for algorithm testing and sensitivity analysis.
  They are not real human participants.
- Clinical Disclaimer: This software is an engineering research prototype.
  It does not provide diagnostic or clinical visual acuity assessment.
